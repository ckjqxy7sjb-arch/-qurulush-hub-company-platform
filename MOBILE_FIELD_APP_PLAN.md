# Mobile field app plan

Дата: 14.09.2026

Этот документ фиксирует контур будущей мобильной версии Qurulush Hub для работников на объекте. Цель - чтобы после запуска основной платформы мобильный клиент подключался к тем же ролям, объектам, поручениям, календарю, чату и журналу аудита без переделки backend.

## Пользователи

- Генеральный директор: видит сводку, просрочки, критичные замечания, платежные риски.
- Главный инженер: распределяет замечания, проверяет доказательства, закрывает техническую готовность.
- Прораб: получает задачи по своему объекту, отправляет статус устранения и фото.
- Бригадир/исполнитель: видит только назначенные замечания, делает фото до/после, добавляет комментарий.
- Бухгалтер и юрист: получают мобильные уведомления, но платежи и юридические действия подтверждают только по своим правам.

## Основные сценарии

- Открыть объект и увидеть только свои замечания, проверки, сроки и поручения.
- Снять фото на телефон, прикрепить к замечанию, добавить короткий комментарий.
- Отправить статус: `new`, `in_progress`, `ready_for_review`, `done`, `returned`.
- Работать при слабой связи: сохранять действия в offline queue и отправлять после восстановления интернета.
- Получить push/чат-уведомление по срочному запросу инспектора, проверке, штрафу или дедлайну.
- Открыть встроенный ИИ-чат и спросить: что срочно, какие документы нужны, какие замечания открыты.

## API contract

- Использовать текущую авторизацию и объектно-ролевой доступ основной платформы.
- Переиспользовать `/api/tasks/{id}/update` для изменения статуса устранения.
- Переиспользовать `/api/documents/{id}/upload` для фото и документов после подключения production storage и AV scanner.
- Переиспользовать `/api/inspections/{index}/prepare` для подготовки проверки.
- Переиспользовать `/api/calendar` для мобильного календаря сроков.
- Переиспользовать `/api/chat` и `/api/chat` POST для внутреннего чата и локального ИИ-помощника.
- Следующим этапом добавить мобильный upload endpoint с `multipart/form-data`, thumbnail, sha256, EXIF stripping, AV verdict и storage reference.

## Требования к запуску

- Мобильный PWA или отдельное приложение должно работать с камерой, сжатием фото и offline queue.
- Нельзя показывать бригадиру чужие объекты, платежи, production readiness и командные настройки.
- Каждое фото и изменение статуса должно попадать в audit с автором, временем, объектом, задачей и результатом проверки файла.
- Массовую фотофиксацию включать только после production storage, AV scanner, лимитов размера файла и политики хранения.
