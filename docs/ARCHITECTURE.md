# Архитектура Qurulush Hub

Qurulush Hub - это кабинет строительной компании для работы с входящими уведомлениями и обязательствами перед ведомственным контуром строительства КР.

## Продуктовая граница

В текущей версии платформа решает задачи компании:

1. Получить уведомление или начисление.
2. Назначить ответственного.
3. Создать поручения внутри компании.
4. Оплатить начисление и сохранить подтверждение.
5. Загрузить документы, фото, акты или комментарии.
6. Отправить ответ и сохранить историю.
7. Контролировать сроки через календарь и чат.

Платформа не содержит отдельные рабочие места министерства, регионального отдела или инспектора. Эти стороны рассматриваются как внешние источники уведомлений, статусов и требований.

## Frontend

- React 18.3 + Vite 5.
- React Router v6 для защищенных маршрутов.
- TanStack Query v5 для серверных данных.
- Zustand 4 для UI-состояния.
- Axios 1.7 для HTTP и refresh-flow.
- CSS Modules + CSS variables для минимального практичного интерфейса.
- react-hot-toast для уведомлений.
- dayjs для дат.
- ExcelJS подключается динамически для выгрузки.
- DOMPurify используется для безопасного вывода текста уведомлений.

## Backend

- Node.js 20 LTS.
- Express 4.19.
- Слои: routes -> controllers -> models.
- PostgreSQL через `pg`, без ORM.
- JWT access token + refresh token в httpOnly cookie.
- bcryptjs для паролей.
- Joi для валидации.
- helmet, cors, express-rate-limit, csurf, cookie-parser, validator.
- multer для загрузок.
- node-cron для напоминаний по срокам.
- Puppeteer и html-to-docx для серверной генерации документов.

## База данных

PostgreSQL, миграции чистым SQL:

- `001_users.sql` - компании, пользователи, токены.
- `002_objects.sql` - строительные объекты.
- `003_notifications.sql` - входящие уведомления.
- `004_tasks.sql` - поручения.
- `005_documents.sql` - документы и файлы.
- `006_payments.sql` - начисления и оплаты.
- `007_chat_audit.sql` - чат, календарь, журнал действий.

Гибкие данные уведомлений и форм хранятся в JSONB, включая QR-код как data-URI при появлении такой интеграции.

## Что удалено из активного продукта

- Министерские demo-кабинеты.
- Реестры инспекторов, региональных отделов и ведомственных отчетов.
- Юридический НПА-справочник как пользовательский раздел.
- Старые readiness, acceptance evidence, launch bundle и release-пакеты.
- Фиктивные ведомственные demo-объекты как основное содержимое.

Эти данные мешали основной задаче компании и не должны быть видны в рабочей версии платформы.
